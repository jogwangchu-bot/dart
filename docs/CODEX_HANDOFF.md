# 로컬 Codex 작업 인계

사용자는 Codex와 GitHub를 처음 사용하며, 프로젝트 폴더를 연결한 뒤 설치·실행·오류 확인·수정·재시험을 에이전트가 직접 진행하기를 원합니다. PC의 파일·터미널을 사용할 수 있는 로컬 작업으로 이어갑니다. API 키의 안전한 최초 입력이나 실제로 필요한 승인 외의 반복 작업을 사용자에게 넘기지 마세요.

## 목표와 자료

- 원본 명세서 `docs/specification.txt`는 클라우드에 보존했으며 GitHub에는 올리지 않았습니다. 이 파일이 없으면 원본을 읽었다고 주장하지 않습니다. 프로그램 설명과 검토 절차는 `README.md`, `docs/REVIEW.md`를 참조하고, 원본 요구사항과의 완전한 대조가 필요하면 사용자가 별도로 제공한 명세서로 확인합니다.
- 현재 검증 현황: `docs/STATUS.md`. 이전 실행 기록은 클라우드에 보존했으며 GitHub에는 올리지 않았습니다. `logs/`의 결과는 PC에서 실제로 실행해 새로 만듭니다.
- 원본 입력 경로: `input/universe.xlsx`. GitHub에는 엑셀이 없습니다. 이 경로가 비어 있으면 사용자 PC의 기존 원본 엑셀을 이 경로로 복사합니다. 파일 위치를 모를 때만 사용자에게 기존 엑셀의 위치를 물어보고, 가짜 입력으로 대체하거나 채팅에 다시 업로드하라고 요구하지 않습니다.
- 기준일 2019-09-18, 정보마감 2019-09-17 23:59:59 KST, 원본 순서의 390종목.
- Windows / Python 3.11 이상. 기존 개발판을 이어서 개선하며 새로 작성하거나 사용자에게 미리 코드를 올리라고 요구하지 않습니다.

## 클라우드에서 확인한 사실과 한계

클라우드 설정 게시 후 DART_API_KEY 변수 존재를 확인했습니다. 그러나 OpenDART API·가이드 모두 접속 중계에서 HTTP 502/upstream proxy failure로 실패했습니다. 키를 사용하지 않는 요청도 동일했습니다. 이 응답으로 키 유효성을 판단하지 않았습니다. 사용자는 PC 브라우저에서 OpenDART가 열린다고 확인했습니다.

실제 OpenDART 원문은 **0건**, 5종목 원문 검증·25종목 검증·전체 수집·Windows 실제 실행·Claude Code 독립검수 모두 미완료입니다. 이 파일을 읽는 시점에 기존 로그를 시험 성공으로 바꾸지 마세요.

Linux에서 자동 테스트 **87개 통과, 실패/오류/건너뜀 0**입니다. 그중 82개는 가짜 응답 테스트, 5개는 공식 DART 웹에서 기록한 실제 목록 메타데이터의 오프라인 후보 선택 테스트입니다. Windows에서 다시 검증해야 합니다.

공식 웹 검색으로 5종목의 2019-01-01~2019-09-17 접수기록은 따로 확인했습니다. `docs/WEB_REFERENCE.md`, `tests/fixtures/public_dart_2019_candidates.json` 참조. 이는 전체 역사 범위·원문·PIT 승인이 아닙니다. 원본 웹 HTML은 클라우드 관리자 캐시에 보존했으며 GitHub에는 포함하지 않았습니다. 필요하면 공식 사이트에서 다시 조회하고 새로운 관측과 해시로 기록하세요.

GitHub 원격은 `jogwangchu-bot/dart`입니다. GitHub ZIP에는 `.git` 이력이 없으며 `git clone`으로 받은 폴더에는 이력이 있습니다. 프로그램 소스를 이미 받은 상태이므로 빈 저장소를 전제로 다시 시작하지 마세요. 원본 입력과 키는 PC에서 별도로 확인합니다. 기존 폴더에서 로컬 작업을 하며 사용자가 요청하지 않은 별도 worktree를 만들 필요는 없습니다.

## 첫 작업 순서

1. 현재 작업 폴더와 로컬 실행 환경을 확인합니다. Windows 네이티브 PowerShell/cmd인지 WSL인지 구분하고, WSL/Linux에서만 통과했다면 Windows 실행까지 확인했다고 보고하지 않습니다. 네이티브 Windows Python을 사용할 수 있으면 그 환경에서 검증합니다.
2. 고정 패키지 목록 `requirements.txt`로 `.venv`를 준비합니다. Windows에서는 `install.bat` 또는 동등한 명령을 직접 실행합니다. TLS·패키지 검증을 끄지 않습니다.
3. 자동 테스트를 실행합니다: `.venv\Scripts\python.exe -m pytest -q tests --junitxml=logs/tests-local-codex.xml`.
4. 실제 입력을 확인합니다: `.venv\Scripts\python.exe -m pit_dart --input input/universe.xlsx --asof 2019-09-18 --expected-count 390 --prepare`.
5. 아래 키 확인·설정을 마친 뒤 동일한 Python으로 `--test --resume` 실행을 진행합니다. 5종목이 끝나기 전 전체 390종목을 실행하지 않습니다.
6. 에이전트가 같은 PC에서 로그·SQLite·ZIP/XML·공식 기록을 직접 읽고 오류 원인을 조사합니다. 수정 후 해당 테스트와 실제 시험을 재실행합니다. 사용자가 매번 로그를 ZIP으로 만들어 전달하게 할 필요는 없습니다.

## 키 처리

클라우드의 비밀정보 설정은 PC 환경변수와 별개입니다. PC의 프로세스 환경과 Windows 사용자 환경변수에 `DART_API_KEY`가 있는지 **이름과 존재 여부만** 확인합니다. 기존 값을 사용할 수 있으면 재입력을 요구하지 않습니다. 값·환경 전체·자격증명 파일을 출력하거나 키가 포함된 URL을 기록하지 않습니다.

없을 때만 사용자에게 PC에서 안전하게 최초 입력하도록 안내합니다. 키 값을 채팅으로 보내라고 요구하지 않습니다. `docs/WINDOWS_KEY.md`의 숨김 입력/사용자 환경변수 설정 방법을 사용할 수 있습니다. 예를 들어 사용자가 직접 여는 PowerShell에서:

```powershell
$pitKeyInput = Read-Host 'OpenDART API key' -AsSecureString
[Environment]::SetEnvironmentVariable('DART_API_KEY', [System.Net.NetworkCredential]::new('', $pitKeyInput).Password, 'User')
Remove-Variable pitKeyInput
```

사용자가 키를 설정한 뒤 이미 실행 중인 앱이 새 사용자 환경변수를 상속하지 못했을 수 있습니다. 필요하면 실제 실행할 PowerShell 안에서 사용자 환경변수를 프로세스에 가져오고, 값을 출력하지 않은 채 Python을 실행합니다.

```powershell
if (-not $env:DART_API_KEY) {
    $env:DART_API_KEY = [Environment]::GetEnvironmentVariable('DART_API_KEY', 'User')
}
& .\.venv\Scripts\python.exe -m pit_dart --input input/universe.xlsx --asof 2019-09-18 --expected-count 390 --test --resume
```

`.bat` 대화형 실행기 `run_pc_5_stocks.bat`는 사용자가 직접 시험할 때 쓰는 보조 도구입니다. 로컬 에이전트가 실행할 때는 키 입력·pause에서 멈추지 않도록 위의 비대화형 CLI와 이미 설정된 환경변수를 사용하세요. 처음 키를 넣는 일 외에는 가능한 작업을 에이전트가 직접 이어갑니다.
